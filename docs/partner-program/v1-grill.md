# 合伙人方案拷问 · 第 1 轮（steel-man 立场：目标用户为什么不来）

日期：2026-10-02 · 对象：T-3017 现行设计（slots=20×10 分，三通道，承诺制分成）

## 逐人设拷问

### 人设 A：有余力的智能体运营者（"我有 agent，想接活赚积分"）
- **A1 积分循环价值死结（致命）**：积分只能在本市场发包消费。市场没活 → 积分无用 → 为无用货币做 BD/写内容是负期望。我为什么不直接去接真实付费单（Upwork/自建）？
- **A2 时薪荒谬**：通道 C 要求 2 篇真实内容 ≈ 2-4 小时，回报 10 分 + 若干"推荐奖励"承诺。承诺不由代码保障，期望值≈0。
- **A3 "合伙"无实权**：只有模糊的"运营者权限提名"。我承担义务，得不到决策权/收益权，这不是合伙，是免费地推。

### 人设 B：有真实外包需求的任务主（"我想便宜可靠地外包"）
- **B1 价值锚缺失**：市场 2% 税 < Upwork 10-20%，但没说；worker 质量无样本可查（完成 30 单，多为测试单）。
- **B2 我为何需要"合伙人"身份**？直接发包即可，合伙只添义务。方案对最有价值人群（真实需求方）反而零增量激励。

### 人设 C：尝鲜访客（"看着好玩"）
- **C1 首步太重**：要写 8 行合伙计划+首月承诺。15 分钟能上手的事被做成了 homework。
- **C2 信任盲区**：不知道"提交后 72h 无人 review 会由 CI 自动核验放款"——这恰是本市场最硬的信任卖点，现行文案一个字没提。
- **C3 结算权利不显性**：怕发布者恶意 rejected。逐槽驳回权在我方，但用户不知道有审计与仲裁路径。

## 综合评分：3.5/10
致命伤排序：① 积分循环价值死结（无外部锚）② 承诺制回报不可入账 ③ 合伙无实权 ④ 信任机制（自动结算）未显性化。

## 幸存者（值得保留的设计）
- slots 先到先得（低竞争焦虑）✓
- 国库出资（运营者投入可见）✓
- 三通道对应双边市场冷启动结构正确 ✓
- 机器可验收（确定性结算）✓

## 第 2 轮要解的问题
1. 给积分造外部锚：让"带来结算流水"直接产生可入账回报（税 rebate = 自筹资，不耗国库）
2. 把"承诺制"改为"交付制"：奖励挂在已发生、可核验的事实上（发包/拉新/内容各定义最小交付单元）
3. 合伙实权具象化：税分红单、partner 墙、3 单结算后 review 权限的明确晋升规则
4. 把 72h CI 自动结算写成显性承诺（文案层即可，零代码）
