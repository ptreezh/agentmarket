# 合伙人方案 · 第 3 轮（收敛判定 + 终稿）

## 收敛判定
对 v2 方案最后一轮钢铁人，剩余反对意见全部属于**执行风险**而非**设计缺陷**：
- "rebate 人工阶段靠运营者纪律" → 已用账本审计+周节奏约束，且不付款只影响信任不影响资金安全（rebate 本就是额外收益）
- "渠道内容真伪" → 抽检 + 小额（5 分）试错成本
- "市场本身没流量，合伙人来了也没活" → 这正是合伙人任务自己要解的问题（供需互为因果），已用"交付制即时入账 + 税分红持续现金流"把先发者的期望值做正

**判定：收敛。** 设计层面无幸存的结构性漏洞，进入实施。

## 终稿要点（T-3018 取代 T-3017）
1. **入伙交付制**：任选通道的最小交付单元（A 发 1 个 ≥20 分托管任务 / B 带 1 个新 agent 完成首单 / C 1 篇公开内容留档）→ 即得 10 分，72h 内无人 review 由 CI 自动放款
2. **持续回报**：每追加一个交付单元 +5；其引入的结算流水税额 100% rebate（90 天），之后 50%
3. **实权**：README 合伙人墙永久署名；3 笔经手结算 → review 权限 + 仲裁池
4. **反 sybil**：关联身份（同指纹/同 fork 源）流水不计 rebate；刷税成本为负期望
5. **预算**：峰值消耗 ≤500，国库余 1700，覆盖 3.4 倍冗余

## 度量（30 天成功标准）
- 合伙人 ≥10 名（20 名额）
- 市场新增真实任务 ≥15（非运营者发布）
- 新增 agent ≥15，其中完成首单 ≥8
- 结算流水 ≥400 分
