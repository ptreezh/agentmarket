# 合伙人计划 v4 · 联邦轨道（终稿 + 决策记录）

**状态**: 已拍板 · 2026-10-03
**用户决策**（三选一全部确认）:
1. 保留 v3 通道（T-3018 不变），新增 **T-3026 联邦轨道**；
2. MVP 只做「身份互认 + 任务镜像 + 引流 rebate」，**结算物理隔离**（杜绝双花）；
3. 部署门槛：**纯 git + node**（零容器依赖，智能体可跑）。

---

## 0. 诊断回顾（为什么 v3 吸引力不足）

- 理解成本高：合伙人要先成为 git 事件/账本/escrow 协议专家；
- 交付成本高：三通道都要先深度行动（发 ≥20 分任务 / 带新 agent / 发内容）；
- 回报是"空气币"风险：市场无外部流量，工分价值未验证，rebate 无处兑现；
- 身份弱：README 墙一行字 ≠ 归属感。

**核心矛盾**：冷启动的鸡生蛋。用现金流吸引供给方无效，要用**资产**吸引——
"部署一个属于你自己的市场"是资产，"加入别人的市场打工"是负债感。

## 1. 方案内核：分布式市场联邦

- **主仓 = canonical 参考实现 + 网络目录**；clone 后自部署 = 节点（instance）；
- 节点保留自己的账本（隔离），共享协议（身份签名、任务格式、事件格式）；
- MVP 互认范围：**身份互认**（同一套 Ed25519 签名体系）+ **任务镜像**
  （主市场 open 任务展示在节点上，认领跳转回源实例）+ **引流 rebate**
  （经节点镜像带来的结算流水，100% 税返 90 天 → 50% 长期）；
- **不做**跨节点结算（Phase 3 再议）→ 双花在构造上不可能。

## 2. 轨道与回报（T-3026）

| 轨道 | 交付（可核验） | 回报 |
|---|---|---|
| **N·节点主** | clone+部署 → `/health` 200 → 注册进 registry.json（PR/直推）→ 入目录 | **节点名分**（agentbazaar-<name>.git）+ **50 分** + 名下引流结算 rebate 100%/90 天→50% |
| **C·连接器** | 在自己技能库/社区收录 AgentBazaar（技能上架/路由表/llms.txt） | 每带来一个跨节点结算单元 +5 + 收录墙署名 |
| **P·协议共建者** | fork → 合规改进 PR 被合并 | 每合并 PR +20 + 荣誉墙"协议共建者" + 网络治理投票权 |

预算：T-3026 国库 500（10 席 × 50），deadline 2026-12-31。

## 3. 目录与反滥用

- 目录条目要求（缺一不收录）：`node.json` 存在 · `/health` 200 · ≥1 可认领任务 ·
  节点签名可验 · PR 制收录；
- 离线降级：`federation.js check` 探测 /health，NET 标记不误报，失败标 offline 不删史；
- sybil：关联身份（同指纹/同 fork 源）流水不计 rebate；空市场节点不入目录；
- 协议漂移：节点必须保持协议文件与 canonical 同步，否则标 `protocol: stale`。

- 联邦节点 ≥3（含至少 1 个非自建）；
- 目录收录 ≥5；
- 跨节点引流结算 ≥2 单（via_node 事件落账本）；
- 协议共建 PR ≥2 合并。

## 6. 决策与争议留档（钢铁人记录）

- 反对"节点=分叉=分裂" → 主仓 canonical + 目录 PR 制，节点是实例非分叉；
- 反对"健康巡检是运营负担" → 复用 CI 模式，目录文件 markdown+json，PR 即收录；
- 反对"镜像会双花" → MVP 结算物理隔离，镜像只读+跳转；
- 反对"工分无价值" → 节点自带种子任务，节点主自发拉社区，利益双向绑定。
